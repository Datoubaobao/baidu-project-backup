# 用户使用手册

本手册面向在本地 Codex 中使用百度网盘保存项目的用户。建议先用一个无敏感数据的小项目完成一次备份与恢复，再处理重要项目。

## 1. 安装与环境

按 [README 的安装步骤](../README.md#安装) 安装技能。官方推荐的个人技能位置为 `~/.agents/skills/`，项目共享技能可放在 `.agents/skills/`；详见 [OpenAI 官方文档](https://learn.chatgpt.com/docs/build-skills)。如果你的环境使用自定义或旧版技能目录，以实际配置为准，避免同时安装同名版本。

本地脚本需要 Python 3.10+，无需额外安装 Python 包。完整桌面流程面向 macOS 和官方百度网盘客户端。需要登录时，请自行在官方界面完成，不向助手提供密码、Cookie、BDUSS、STOKEN 或访问令牌。

自动操作客户端需要当前环境提供桌面控制工具。Codex CLI 等缺少此能力的环境可以让用户手动传输，助手仍负责打包、校验和恢复。技能不会自动安装客户端、网盘插件或网络代理。

## 2. 选择备份方式

| 你的要求 | 本地项目结果 |
| --- | --- |
| 备份当前项目 | 保留全部原文件，校验成功后添加恢复标记与说明 |
| 备份并清理当前项目 | 校验成功、源文件未变化后，移入废纸篓并在原路径留下三个恢复文件 |
| 恢复完整项目 | 先恢复到新目录，核对成功后可安装回原路径 |
| 恢复指定文件或子目录 | 只下载涉及的分卷，恢复到新目录 |

只处理当前对话确定的项目目录。不会把上级桌面、其它工作区目录或符号链接指向的外部文件顺便上传。项目备份包含隐藏文件、`.git`、`.env`、依赖和临时目录；如有范围限制，请在开始前明确说明。

## 3. 完成一次备份

1. 保存编辑器中尚未保存的内容，暂停会改写这个项目的构建、生成和编辑任务。
2. 在 Codex 中说：“使用 $baidu-project-backup 将当前项目备份到我的百度网盘，保留本地文件。”
3. 助手检查当前项目、网盘入口和磁盘空间，并生成分卷与文件清单。默认每卷上限 2 GiB，不压缩视频；同磁盘通常需要项目体积约两倍的额外空间及余量。
4. 将这次生成的所有分卷、清单、信息文件上传到独立的网盘版本目录。已有版本会保留。
5. 从该远端目录把所有分卷和清单重新下载到全新、独立的目录。
6. 助手核对分卷 SHA-256、清单和每个归档文件，成功后写入本地恢复入口，并报告真实网盘位置。

默认网盘目录结构为：

```text
/Codex项目备份/<项目名>-<路径摘要>/<带时区时间戳>-<随机编号>/
  project.tar.part00001
  project.tar.part00002
  ...
  manifest.json
  backup-info.json
```

网盘中的文件夹应直接包含这些文件；客户端若额外套了一层同名目录，需要核对并修正实际位置。不要手动拼接或解压分卷，优先使用本技能恢复。

上传队列显示 100%、文件大小相同或已加入任务，都不代表备份可以恢复。必须完成真实回下载及全部内容校验。脚本无法从一个本地目录判断文件是否真的来自云端；操作人员需如实保留传输来源证据。

## 4. 备份并清理

在项目中说：“使用 $baidu-project-backup 备份并清理当前项目。”

完整上传、回下载和校验成功后，助手会再次检查源项目。新增文件、内容变化、缺失文件或被改写的恢复标记都会阻止清理；应将变化纳入新版本，再验证后继续。

清理会把原项目整体移动到同一文件系统的废纸篓目录，随后在原路径只留下：

| 文件 | 用途 |
| --- | --- |
| `AGENTS.md` | 下次 Codex 打开项目时读取恢复提示；原有文件已保存在备份里 |
| `.codex-baidu-backup.json` | 备份编号、网盘路径、校验值、独立索引位置 |
| `百度网盘恢复说明.md` | 用户可以直接阅读的恢复说明 |

**移入废纸篓不会立即释放空间，本技能不自动清空废纸篓。** 外置盘项目若与废纸篓跨文件系统，脚本会停止清理；保留源项目，或在同一卷选择明确、专用的暂存废纸篓目录。手动指定的目录可能不会显示在 Finder 废纸篓中，需自己保存好路径。

只有远端验证和所要求的清理完成后，才考虑删除本次生成的打包、回下载临时副本。仅删除已经明确识别的本次临时文件；保留独立索引、源文件所在的废纸篓及所有旧远端版本。

## 5. 恢复完整项目

在原项目的标记目录中对 Codex 说：“使用 $baidu-project-backup 恢复这个项目，并继续在原路径工作。”

助手读取恢复标记，定位精确的网盘版本目录，下载全部分卷和清单，在旁边一个尚不存在的新目录中恢复并核对内容。原路径为空或只有本技能未被修改的三个标记文件时，可以安装回原路径。原路径已有新文件时，保留新旧两份，先报告位置并处理冲突，不覆盖新工作。

完整恢复会还原原有 `AGENTS.md`。如果只需找回资料，不要求继续原项目，也可直接保留新恢复目录。

## 6. 只恢复一个文件或子目录

示例：“使用 $baidu-project-backup 恢复项目中的 output/report.pdf，放到新的恢复目录。”

先下载 `manifest.json`，再由 `needed` 计算所需分卷，仅下载计算结果并校验。文件跨卷时需要涉及的全部分卷；零字节文件、目录和符号链接可由可信清单恢复。结果仍保留原相对路径，例如新目录下的 `output/report.pdf`。

符号链接仅恢复链接本身，不会顺便下载链接指向的外部内容。部分恢复不能直接用 `install` 替换整个项目。

## 7. 索引和标记在哪里

默认本地状态根目录为 `~/.codex/project-backups/`，与技能安装位置无关：

```text
~/.codex/project-backups/
  records/<备份编号>.json
  staging/<备份编号>/...
```

项目标记目录被删后，仍可按原项目路径在 `records/` 中寻找对应记录。不要仅凭同名项目选择版本。索引保存可信校验值，建议另存一份到自己的安全位置；它包含本机路径等信息，请勿公开。

脚本恢复时使用本地 `record`，不支持仅凭公开分享链接恢复。若电脑丢失或迁移设备，请先从自己的安全副本找回索引；路径可能需要人工核对迁移。索引完全丢失时，不应凭新下载文件自行编造校验值并宣称完成可信恢复。版本目录中的 `backup-info.json` 可提供定位线索，不能代替原始可信索引。

## 8. 没有桌面控制工具时手动传输

助手先输出本次 `staging_dir`、`remote_path` 和 `record`，用户再通过官方客户端：

1. 在自己的网盘中创建与 `remote_path` 完全一致的目录。
2. 上传暂存目录内全部 `project.tar.partNNNNN`、`manifest.json`、`backup-info.json`。
3. 等本次上传全部完成，进入远端版本目录核对文件名和数量。
4. 从该远端版本目录重新下载所有分卷和 `manifest.json` 到全新独立目录。
5. 将真实下载目录及可识别的账号短标签告知助手，继续 `verify`；不要提供完整手机号或凭据。

手动传输与自动操作使用相同的校验要求。下载未完成、缺卷或账号位置不确定时，保留源文件。

## 9. 本地命令参考

大多数用户直接向 Codex 提出要求即可。以下供需要手动操作或排查问题的用户使用。示例中的项目、索引和下载目录必须替换为本次实际路径；带空格或中文的路径始终加引号。

```bash
BACKUP_SCRIPT="$HOME/.agents/skills/baidu-project-backup/scripts/backup.py"

# 生成本地归档；只代表本地准备完成
python3 "$BACKUP_SCRIPT" prepare --project "/path/to/project"

# 使用外置盘暂存，或自定义网盘父目录（可选）
python3 "$BACKUP_SCRIPT" prepare --project "/path/to/project" \
  --staging-root "/Volumes/BackupDisk/staging" \
  --remote-root "/项目归档"
```

记下输出的 `record`、`staging_dir`、`remote_path`。后续命令中的索引路径来自该输出，不自行猜测编号：

```bash
BACKUP_RECORD="/path/to/records/backup-id.json"
BACKUP_DOWNLOAD="/path/to/actual-cloud-download"

# 失败后先检查现有归档能否继续用，避免重复打包大项目
python3 "$BACKUP_SCRIPT" check --record "$BACKUP_RECORD"

# 此处必须先在官方客户端完成真实上传和独立回下载
python3 "$BACKUP_SCRIPT" verify --record "$BACKUP_RECORD" \
  --download-dir "$BACKUP_DOWNLOAD" --account-label "本人网盘（已核对）"
```

`verify` 校验下载内容并写恢复标记。账号标签由操作者核对，参数自身不验证账号或云端来源。以下命令只有已明确要求“备份并清理”时才执行：

```bash
python3 "$BACKUP_SCRIPT" cleanup --record "$BACKUP_RECORD" \
  --authorization backup-and-cleanup
```

恢复到尚不存在的新目录（父目录需要存在）：

```bash
# 完整恢复：下载目录中必须有全部分卷和 manifest.json
python3 "$BACKUP_SCRIPT" restore --record "$BACKUP_RECORD" \
  --download-dir "$BACKUP_DOWNLOAD" --destination "/path/to/project-restored"

# 完整恢复后，如原路径满足保护条件，可安装回原路径
python3 "$BACKUP_SCRIPT" install --record "$BACKUP_RECORD" \
  --restored-dir "/path/to/project-restored"
```

指定文件恢复，可单独操作：

```bash
# 先从精确的远端版本目录下载 manifest.json
python3 "$BACKUP_SCRIPT" needed --record "$BACKUP_RECORD" \
  --download-dir "$BACKUP_DOWNLOAD" --only "output/report.pdf"

# 再从同一远端目录下载上一步列出的 parts；随后执行
python3 "$BACKUP_SCRIPT" restore --record "$BACKUP_RECORD" \
  --download-dir "$BACKUP_DOWNLOAD" --destination "/path/to/recovered-files" \
  --only "output/report.pdf"
```

`prepare` 还支持 `--state-root`（默认 `~/.codex/project-backups`）和 `--chunk-mib`（默认 2048）；`cleanup`、`install` 支持 `--trash-dir`。暂存、状态、下载和恢复目录应在源项目之外；恢复目标不能覆盖现有目录。完整帮助：`python3 "$BACKUP_SCRIPT" --help` 或在子命令后加 `--help`。

## 10. 常见问题

| 情况 | 处理方式 |
| --- | --- |
| 网盘未登录、网络异常或没有客户端 | 在官方客户端完成登录或修复接入；保留项目，准确区分本地准备、上传、回下载阶段 |
| 上次上传中断 | 先运行 `check`；归档和源文件仍一致时续用本地归档，有变化则制作新版本 |
| 磁盘空间不足 | 使用外置盘存放暂存与独立回下载副本；空间不足以完成校验时不清理 |
| 下载缺卷、文件损坏或清单不匹配 | 重新从精确远端目录下载相应文件；全部校验通过前不清理 |
| 清理时报告源文件变化 | 包括 `.DS_Store` 在内的变化都会阻止清理；暂停改写并备份新版本，不绕过检查 |
| 跨卷移动被拒绝 | 保留源项目，选择同卷专用 `--trash-dir` 或保留独立恢复目录；不改成永久删除 |
| `.git` 是 worktree 指针文件 | 根 linked worktree 会被拒绝；优先使用原生 worktree 归档，或单独规划完整 Git 存储备份 |
| 恢复目标已存在或原路径有新内容 | 使用新目录，不覆盖新工作；先人工处理冲突 |
| 提示路径穿越、不安全链接或特殊文件 | 停止并检查项目/归档，不能关闭检查强制继续 |
| 移入废纸篓后磁盘没变小 | 属于预期行为；本技能不清空废纸篓 |

## 11. 隐私、限制与自测

分卷为未加密的 tar 数据切片，文件清单、扩展属性、索引和信息文件可能暴露文件名、项目绝对路径、配置或密钥。上传前确认这些内容可以存入自己的网盘；需要加密时应先另行规划并验证完整加密恢复方案，当前技能不提供加密功能。

不要把真实分卷、清单、索引、恢复标记、截图、传输日志或登录信息提交到 GitHub。公开提问请使用虚构目录和合成数据，见 [安全说明](../SECURITY.md)。

当前保存文件内容、POSIX 权限、纳秒修改时间、可用的扩展属性和符号链接。硬链接按独立文件保存，不保留共享 inode；ACL、所有者、特殊设备、应用未保存内容和 Codex 服务端聊天记录不在完整还原范围内。跨平台或不支持扩展属性的文件系统需要独立验证，不能直接承诺等价恢复。

开发自测在仓库根目录运行：

```bash
python3 -B scripts/test_backup.py
```

测试在系统临时目录生成合成项目，模拟上传结果的本地副本，以验证归档、保护条件、部分恢复和安装行为。它不连接百度网盘，不构成任何真实项目已经完成云端备份的证明。
